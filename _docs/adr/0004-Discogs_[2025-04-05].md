# ADR 0004: Использование Discogs API как основного источника метаданных с абстракцией для MusicBrainz

## Контекст
Playlist AI требует точные метаданные треков (название, исполнитель, альбом, жанр, год) для сканирования и генерации треклистов. Локальные теги, извлекаемые через Mutagen, часто неполные (например, жанр в CSV как `Unknown`), что ограничивает функциональность. Для pet-проекта нужен надёжный внешний источник метаданных, с перспективой подключения дополнительных источников для большей полноты данных. Сейчас метаданные (`title`, `artist`, `album`) берутся из локальных тегов через Mutagen, Discogs API пока не интегрирован (но есть библиотека python3-discogs-client), а MusicBrainz рассматривается как будущий дополнительный источник. Модели (Track, Album, Artist) включают поля `external_ids`, что поддерживает интеграцию с внешними сервисами.


## Решение
Использовать **Discogs API** как основной источник метаданных с абстракцией для будущей поддержки **MusicBrainz**:
- **Discogs API**: Извлекает `title`, `artist`, `album`, `genre`, `year`, `label` и др., интегрируется через библиотеку python3-discogs-client.
- **MusicBrainz**: Планируется как дополнительный источник в перспективе (через библиотеку, например, musicbrainzngs), для обогащения данных, недоступных в Discogs.
- **Абстракция**: Реализовать слой `api/interfaces` (интерфейсы для клиентов) и `api/clients` (конкретные реализации для Discogs, MusicBrainz), чтобы упростить подключение новых источников.
- Интеграция с SQLAlchemy через `external_ids` для хранения идентификаторов от разных сервисов.
- Текущая реализация использует Mutagen, с планом подключить Discogs API и позже MusicBrainz.


## Альтернативы

- **Только MusicBrainz** — Открытая база с широким охватом, но API сложнее, а интеграция требует больше усилий на старте.

- **Spotify API** — Готовые метаданные и анализ, но ограничен треками из Spotify и требует авторизации.

- **Только локальные теги (Mutagen)** — Простота и отсутствие зависимостей, но данные неполные (жанр как Unknown, год часто отсутствует).

- **Gracenote** — Коммерческий сервис с высоким качеством, но платный и избыточен для pet-проекта.


## Последствия

- Discogs API обогатит метаданные (жанр, год, лейбл), улучшив классификацию и генерацию треклистов.

- Абстракция через api/interfaces и api/clients упростит подключение MusicBrainz и других источников в будущем.

- MusicBrainz как дополнительный источник повысит полноту данных, особенно для редких треков.

- Зависимость от интернета и лимитов API (Discogs: 1000 запросов/день, MusicBrainz: rate limiting) может ограничить сканирование больших коллекций.

- Требуется обработка ошибок и сопоставление данных между сервисами (например, разные ID в external_ids).

- Текущая зависимость от Mutagen сохраняет простоту, но ограничивает полноту до интеграции API.

- Реализация абстракции увеличит начальные затраты, но окупится при расширении.


## Статус
**Принято**
